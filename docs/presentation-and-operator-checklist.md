## The Analyst Cockpit

The current evidence supports Windows endpoint alerts and selected firewall
records, plus separately labeled Suricata validation alerts. It does not support
a complete record of Windows browsing or iPhone traffic. Suricata's permanent
service was left masked after the trials; an installed program is not a live feed.
A stopped sensor and a saved alert visible in a dashboard can coexist.

For one available record, work through this sequence:

1. Check the source and its freshness. A successful loader alone is insufficient.
2. Identify event time, source/channel, rule, severity and processing/load times.
3. Read the actual match conditions and surrounding evidence, not only the title.
4. Classify the observation as controlled test, unresolved activity or supported
   investigation outcome. A previous benign case is context, not a new verdict.
5. Trace the exact alert identity into SQL; Power BI reflects its last refresh.
6. Record evidence, uncertainty and any action. Keep raw records private.

Use the [learning runbook](analyst-toolkit-runbook.md),
[packet-to-report lesson](L0-event-to-report-trace.md) and
[interaction audit](triage-system-audit.md). A later creative traffic-reading
exercise can compare one harmless positive and one nonmatch on an owned, verified
path, with automatic stop and packet/drop checks. That is a proposed exercise,
not browsing coverage or authorization to capture now.
